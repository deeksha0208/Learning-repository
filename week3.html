Week 1: Git and GitHub Fundamentals

Understanding Version Control and Project Management

1. Understanding Version Control

Version control is a method of recording changes made to files over time. It allows developers to review previous versions, correct mistakes, and work on software projects in an organized manner.

Git is a popular version control tool that helps developers maintain a complete history of their project changes.

2. Exploring GitHub

GitHub is a web-based service that stores Git repositories online. It allows users to publish their projects, share source code, review contributions, and work together with other developers.

For example, a student can upload a college project to GitHub and share its repository link with a teacher or interviewer.

3. Important Git Terminology

  • Repository: A project folder that contains files and their version history.
  • Commit: A recorded set of changes saved in the repository.
  • Branch: A separate line of development used to work on features independently.
  • Merge: The process of combining changes from different branches.
  • Working Directory: The files and folders where changes are made.
  • Staging Area: The place where selected changes are prepared for a commit.
  • Remote Repository: A repository stored on an online server, such as GitHub.

4. Git vs GitHub

Git GitHub
A version control system. An online repository hosting platform.
Tracks changes made to project files. Stores and shares repositories online.
Can work locally on a computer. Supports collaboration through the internet.
Provides commands for managing versions. Provides tools for code reviews and teamwork.

5. Useful Git Commands

Command Explanation
git init Creates a new local Git repository.
git status Shows modified, staged, and untracked files.
git add . Stages changes in the current directory.
git commit -m "message" Records staged changes with a message.
git log Displays previous commits.
git clone URL Downloads a copy of a remote repository.
git push Sends local commits to a remote repository.
git pull Downloads and integrates remote changes.

6. Steps in a Typical Git Workflow

  1. Create a project or modify existing files.
  2. Initialize Git if the folder is not already a repository.
  3. Check file changes using git status.
  4. Select changes with git add ..
  5. Save a version using git commit.
  6. Connect to a remote repository if necessary.
  7. Upload the saved commits using git push.
Example:

git add .

git commit -m "Initial project version"

git push
